### 方針

- **元の版の更新は取り込まない前提にする**（こだわらない。決まりは [development.md](development.md) と `CLAUDE.md` に反映済み）
  - **README を書き直す**（公開の前に必須。パートナーの助言）
    - 今の仕様にきっちり合わせる。今の README は元の版のままで、削った機能（プレビュー、フローティング、自然言語の日付、TODO の引き継ぎ）や
      元のコマンド名・設定の説明が残っている
    - 改造版であることを明記する: 元の版（luiisca/obsidian-periodic-notes-calendar）の名前とリンク、元の作者のクレジット、
      改変したこととその日付、ライセンス（GPL-3.0）
  - CHANGELOG・release-please・`.github/` は自分の公開手順に合わせて作り直すか消す
  - `upstream` の remote は、元のコードを見比べる参照用に残すか決める
- **ライセンスは厳しいほうに従う**（パートナーの助言）
  - 元の版の LICENSE は GPL-3.0（`package.json` だけ MIT だった）。厳しいほうの GPL-3.0 に従い、改造版も GPL-3.0 で公開する
    （GPL の作品を改変したものなので、MIT などに変えることはそもそもできない）
  - 元の作者の著作権表示とクレジットを残す。改変したことと日付を示す（README の告知で済ませている）
  - 同梱している部品のライセンス表示: ビルドした `main.js` には依存パッケージ（emoji-mart、@emoji-mart/data、
    @floating-ui/dom、clsx、emoji-regex、uuid、svelte など）が入る。それぞれのライセンスを確かめ、求められる表示を
    `THIRD_PARTY_NOTICES.md` などにまとめる
  - `src/ui/utils/emoji-keywords/ja.json` は Unicode CLDR のデータから作ったもの。Unicode のライセンスが求める表示（著作権表示とライセンス文）を添える
- **自分が使わない機能は削る**（メンテナンスが大変なため。パートナーの助言）
  - 2026-10-29 に、プレビュー欄・フローティング表示・minimal mode の切り替え・TODO の引き継ぎ・自然言語の日付を削った
    （[customizations.md](customizations.md) の「削った機能」）。残す・作り直すと決めたもの:
    - 残す: 起動時にノートを開く、テンプレートの基本の置き換え、カレンダーの言語の切り替え（作りは直す）、ステッカー、
      1 つの周期に複数のフォーマットを持つ機能（自分は使わないので手入れの優先度は低い）
    - 作り直す: 周期ノートでないノートにもタイムラインを出す機能（不具合 (4)。タイムラインの作り直しと一緒に）

## 1. 直すべき不具合

(2) は 2026-10-28 に Cursor がコードを読んで見つけたもの、(4) は 2026-10-29 に見つけたもの。
番号は付けたときのまま（(1) は 2026-10-29 に直した。(3) はプレビュー欄と一緒に消えた）。
(2) はコードを読んでの判断で、Obsidian ではまだ再現を確かめていない。どちらも状態管理の作り直し（「2. やりたいこと」）で直す。

- (2) 関係ないファイルを消すと、カレンダーの選択が外れる（`onFileDeleted`）
  - 消したファイルが今開いている周期ノートかどうかを見ずに、`activeFileStore` と `timelineParentFileStore` を空にしている
    （元のコードのコメントにも `this will add some cognitive load for sure` とある）
  - 別の日のノートや、周期ノートでない `.md` を消しただけでも、開いている日の選択の強調が消える。
    タイムラインの親が空になるのは、次の `layoutSync` で付け直されるだけなので実害は小さい
  - 直し方: 消したファイルが今の選択（とタイムラインの親）と一致するときだけ外す
- (4) タイムラインの付け替えが不安定（`src/ui/components/timeline/manager.ts`）
  - 症状（「ふつうのノートにも出す」をオンにしたとき、2026-10-29 に Obsidian で確認）: 月次ノートを開いても月次のタイムラインに
    切り替わらないことがある。ふつうのノートを開いたとき、畳まれたり畳まれなかったりする。前のノートの表示（月）が残る
  - 原因（コードを読んでの推定。再現手順で確かめる）:
    - **「今どのノートのタイムラインを出しているか」を、全体で 1 つの値（`timelineParentFileStore`）で覚えている。** タブ（リーフ）ごとではない。
      `layoutSync()` は、開いたノートがこの値と同じなら何もしない
    - しかもこの値は周期ノートのときしか更新しない。ふつうのノートにタイムラインを付けても、値は前の周期ノートのまま残る
      - 再現手順の予想: 月次ノート M を開く → 同じタブでふつうのノート N を開く（N 用の「今日の週」のタイムラインに替わる）→ M に戻る。
        値は M のままなので「もう M のタイムラインがある」と判断して何もせず、M に N 用のタイムラインが残る
      - **オフでも起きるはず**: M → N（タイムラインを外す）→ M で、M にタイムラインが出ない
    - 周期ノートどうしでタブを行き来すると、そのたびに作り直すので、週の移動や開閉の状態が毎回戻る
    - 畳むかどうかは、付けたときのペインの幅（640px より広いか）と設定（周期ノートは `viewMode`、ふつうのノートは `restViewMode`）で決まる。
      幅を測るのがペインの準備前だと 0 になり畳まれる。その後は `ResizeObserver` が幅の変化で開閉を切り替える（しきい値が 620・640・660 でばらばら）
    - 外すとき（`unmount(leaf)`、`mount` の中の `isMountedIn(leaf, true)`）は DOM の要素を消すだけで、Svelte の `unmount` を呼ばない。
      部品の後片付け（`ResizeObserver` の解除、ストアの購読の解除）が動かず、残り続ける。`components` は `file.path` で覚えているので、
      同じノートを 2 つのタブで開くと片方を見失う
  - 直し方（作り直し）: タブ（リーフ）ごとに「出しているタイムラインと、その対象のノート」を覚える（例: `WeakMap<WorkspaceLeaf, { file, component }>`）。
    ノートを開いたとき・タブを切り替えたときは、そのタブのノートと覚えているノートが違うときだけ付け替える。外すときは必ず Svelte の `unmount` を使う。
    開閉の初期値は、幅ではなく設定と前回の状態で決める
  - 方針（2026-10-29）: 部分的に直すのではなく、タイムラインの状態管理を設計し直す。下の「状態管理の作り直し（リファクタ段階 3）」と一緒に考える

    週次ノートが無効なら出さない
  - 決めること: 月をまたぐ週の前後の月の日も含めるか、タイムラインの週の見出しも同じ表現にするか、日付の選択（濃い塗り）と重なったときの見え方。
    決める前に A・B・C の見た目の試作を作る
- 設定画面の整理（機能の整理が終わったら）
  - 今は「Calendar」と「Periods」のタブがあり、「Calendar」タブの中にステッカー・タイムライン・プレビューなどの設定が詰め込まれている
  - 機能ごとの階層構造を考え直して、タブや見出しを組み直す

## 3. 必要になったら

- 移行（既存のノートの名前を、新しい書式に付け替える）を、書式の切り替えとは別の機能として作る（2026-10-29 に、切り替えと移行を分けると決めた）
  - 今は、新しい書式の行の「ほかの書式のノートを、この書式の名前に付け替える」ボタン（元の版の機能。週の読み違いとリンク切れは直した）で代わりになる
  - 作るときに考えること: 切り替えた直後に「古い書式のノートが N 件ある」と知らせて移行へ案内する、付け替えの前に一覧（変わる名前）を見せる、
    移行が済んだら古い書式を消せると案内する
  - 置き場所（2026-10-29 の案）: 設定画面に移行をまとめる場所（「移行・メンテナンス」の見出しなど）を作り、ほかの移行（元の版のステッカーのタグを
    プロパティへ）と並べる。あわせて、古い書式を × で消すときの確認にも「この書式でしか読めないノートが N 件。先に付け替えますか」と出して、
    そこから移行に進めるようにする
- 複数のフォーマットの「消す」確認で、ファイル数が不正確（2026-10-29 に気づいた）。`YYYY-[W]ww` と `GGGG-[W]WW` のように同じ名前になる書式が
  2 つあると、同じファイルが両方に数えられ、「このフォーマットを使っているファイルが 2 つ」と出る。実際はもう一方の書式でも読めるので、
  消しても困らない。「この書式でしか読めないファイル」の数を出すようにする
- 週の決め方を選べるようにする（要望が出たら。[periods.md](periods.md) の ADR-006 で差し替えられる形にしておく）
  - 例: 火曜など土・日・月以外の週の始まり、1 月 1 日を含む週を第 1 週にする、年で切る週。そのモードでは週番号の付け方も選べるようにする
- 「カレンダーは開いたノートに付いてこないでほしい」設定（2026-10-29 に設定「Auto-sync calendar date」ごと削った）。
  別の月を見たままほかの場所からノートを開く使い方で困る人がいたら、設定を足し直すか考える
- 「昨日・明日のノートを開く」コマンド（2026-10-29 に検討して見送り）: 「Open today's note」→「Open previous/next periodic note」の
  2 回で届くので作らない。今日のノートを経ずに明日へ行くことが多いと感じたら、`tomorrow` / `yesterday` の名前で作る
  （月なら「last month's / next month's」と言えるので、名前は作らない理由にはならない）
- フローティング表示・プレビュー欄を作り直す（2026-10-29 に一度削ると決めたもの。優先度低）
  - プレビューを作るなら、Obsidian 標準のホバープレビュー（コアプラグイン「ページプレビュー」。エクスプローラーでファイル名にホバーすると出るもの）と
    一貫した形にする。先にその機能と、オン・オフの設定のしかたを調べる
  - 今のカレンダーのホバー（`src/ui/utils/event-handlers.ts` の `onHover`）は、その標準機能を `hover-link` イベントで呼んでいるだけ。
    出所を `source: "preview"`（借り物）にしているので、ページプレビューの設定画面に Calendared の項目が出ない。
    `registerHoverLinkSource` で自分の出所を登録すれば、標準の設定画面でカレンダーのオン・オフ（Ctrl/Cmd 必須かどうか）を切り替えられるはず。
    今ある設定「Hover preview」（`autoHoverPreview`）との関係も合わせて考える
- 自然言語の日付（「来週の金曜」でノートを開く、テンプレートの `{{next friday}}`）を作り直す（2026-10-29 に一度削ると決めたもの。優先度低）
- 絵文字ピッカーの乗り換え: 候補は emoji-picker-element（多言語のデータ emojibase で検索できる）。emoji-mart の更新が止まって困ったら
- ステッカー関連
  - カレンダーの日付（や月）をダブルクリックして、ステッカーのピッカーを開く（近道）
    - そのノートを開いているときだけ有効にする。開いている日付のクリックは同じノートを開き直すだけなので、
      ダブルクリックをピッカーに割り当てても余計なことが起きず、ふだんのクリックも遅れない
    - 判定は「1 回目のクリックの時点で、すでに開いていたか」で行う（まだ開いていない日付を癖でダブルクリックした人にピッカーを出さない）
    - 隠れた操作なので、見える入口（見出しバーのボタン、コマンド、カレンダーの右クリック）の近道という位置づけ。スマホのダブルタップは要確認
  - 元の版のステッカー（本文のタグ）をプロパティに移す移行機能を、ステッカー機能とは別に作る
    - 書き換える前に、対象のノートと変更内容の一覧を見せる。ステッカーのつもりでないタグを書き換えないよう、対象を選べるようにする
