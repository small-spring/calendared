# これからやること

作業の一覧はここだけに書く（機能・不具合も、公開の手続きも）。決まりや要件などの参考は [guides/](guides/)、設計は [plans/](plans/) にある。

- 見出しは進める順（機能を詰める / パートナーに使ってもらう / 公開するか決める / 公開すると決めたら / いつか / 見送ったこと）。不具合か機能かは各項目の頭に書く
- 同じ見出しの中は、上から順に取りかかる。項目を別の見出しに移すのは自由（決めたら日付を添える）
- 終わったものはここから消し、[customizations.md](customizations.md) に 1〜2 行で足して〔日付〕を付ける
- 検討して作らないと決めたものは消さずに「見送ったこと」に移し、理由と、見直すきっかけを残す

2026-10-30 に、進め方を「機能を詰める → パートナーに使ってもらい、フィードバックをもらう → 公開するか決める」にした
（[ADR-0028](adr/0028-decide-publishing-after-feedback.md)）。公開の手続きは、公開すると決めるまで手を付けない。

## 1. 機能を詰める

わかっている不具合と、作ると決めた機能を片づける。iPhone での確認などで見つかったらここに足す。

### 機能・不具合

2026-11-01 に、古いコードと想定と違いそうな動きをもう一度洗い出したもの。「たぶん」は、コードを読んだだけで、起きるかをまだ確かめていない — どれも Claude

- 不具合: 書式の重複チェック（`src/io/validation/format.ts` の `checkIfDuplicateFormat`）が、ほかの周期のまちがった書式とも比べる。
  月の書式に日と同じ `DD.MM.YYYY` を入れて設定画面を閉じると、日の正しい書式まで既定に戻る。書式は周期ごとに使える記号が違う
  （[ADR-0040](adr/0040-format-tokens-per-period.md)）ので、正しい書式どうしはぶつからない。チェックごと消せるか考える
- 不具合: 四半期・年を 1 月以外から始めたとき、書式の `y`・`yyyy`・`yo`・`YYYYY` が暦の年で書かれる（`src/periods.ts` の `withNameNumbers`）。
  作ったノートがカレンダーに出ず、作り直される。ADR-0040 の表では年の記号は `YYYY YY Y` だけなので、`src/format-tokens.ts` で許すものを表に合わせる。
  年が足りないときの文言「year (Y, y, gg or GG)」も、その周期で使える記号だけにする
- 不具合: 大文字・小文字だけ違う名前への書式の変換（`2026-w44` → `2026-W44`）が、ノート自身とぶつかったことになる（`src/migrations.ts` の `planFormatRenames`）。
  [spec/migrations.md](spec/migrations.md) では、ぶつかるのはほかのファイル
- 不具合: カレンダーの言語に `x-pseudo`・`oc-lnc` を選ぶと、パンくずの月・日の表記（`Intl.DateTimeFormat`）がエラーになる（`src/navigation.ts`、`Navigation.svelte`）。
  月・日の表記を moment にそろえるか、Intl が知らない言語を一覧から外す
- 不具合: 設定を変えても、開いているノートのパンくず・ミニカレンダーが古いまま（`src/ui/components/navigation/sync.ts` は、同じノートなら作り直さない）。
  書式・週の始まり・四半期と年の始まりの月を変えたとき。ノートの読み取り結果も比べる
- 不具合: 起動時に開くノートだけ、日付に「今」を渡す（`src/main.ts`）。週・月・四半期・年のテンプレートの `{{date}}` が、コマンドや Open now で作ったとき
  （その期間の最初の日）と違う
- 不具合: 周期をオフにすると、その周期の移行の知らせが Migrate notes の警告に残るのに、押せる行が出ない（`src/settings/plugin-tab.ts` の `anyMigrationNotice`）
- 不具合（たぶん）: 書式を入力して 0.5 秒以内に設定画面を閉じると、閉じるときの確かめのあとで、まちがった書式が保存される（`Format.svelte` の `debounce`）
- 不具合（たぶん）: 設定画面を閉じるとき、オフの周期の書式も確かめて黙って既定に戻す（`plugin-tab.ts` の `hide`）。オフの周期の書式は、今あるノートを開くのに使っている
- 不具合（たぶん）: カレンダーがエディタの場所にあって選ばれているとき、カレンダーを開く・閉じるコマンドで、中身のないビューが残る（`src/main.ts` の `leaf.view.unload()`。元の版のコード）
- 不具合（たぶん）: テンプレートの候補を出したまま設定画面を閉じると、矢印キー・Enter の割り当てが残る（`src/settings/ui/suggest.ts` の `destroy` が `close` を呼ばない）
- 不具合（たぶん）: ステッカーのピッカーを別ウィンドウのノートから開くと、メインのウィンドウに出る（`src/ui/sticker-picker.ts` が `document`・`window` を使う）
- 不具合（たぶん）: Markdown でないファイルの名前を変えても、書式がまちがっているという知らせが出うる（`main.ts` の `onFileRenamed` に `.md` の確かめがない）
- 整理: 元の版の、使われない設定を読み込むときに捨てる（`REMOVED_SETTINGS` に `stickerPrefix`・`lastUsedStickerPrefixes`・`shouldConfirmBeforeStickerMigrate`、
  1.2 より前の `viewLeafPosition`・`leafViewEnabled`・`validFormats` など）。設定を読み込むときの重ね方が 1 段だけなので、入れ子の設定に足した項目の既定値が入らないのも直す
- 整理: 使われていないものを消す: `src/ui/components/navigation/index.ts`、`trim()`・`basename()`、`WorkspaceLeaf.height`、`openState`、`localeDataStore.weekdays`、
  `IMonth`/`IWeek` の再エクスポート、`#emoji-modal` の CSS、点の白抜きの表示、`suggestionsContainerCreated`。最初の起動の余分な保存と、`main.ts` のずれたコメントも
- 整理: カレンダーのマスに何百も付いている同じ `id`（`id="dot"`、`id="date-text"` など。どこからも使われていない）を消す
- 整理: 週の計算を、週の決め方の部品（[ADR-0014](adr/0014-swappable-week-scheme.md)）に聞く形にそろえる（`navigation.ts` の `isoThursday`、
  `calendar-locale.ts` の `monthGrid`、`weeks.ts` の `isoWeekFormatFor` は書式を記号に分ける部品も使う）
- 整理: 画面の部品の後片づけ（確認のモーダル、ファイルの候補、書式の知らせで、作った Svelte の部品を消していない）。`DateBttn.svelte` の `isAdjacentMonth` を `$derived` に。
  曜日の見出しを、週の並びと同じ設定から作る（`localeDataStore` をなくす）
- 整理: 小さな文言など: 矢印のツールチップ「Previous Month」を文の書き方に（「Range」もわかりにくい）、「Create note」のアイコン `document` を確かめる、
  `src/locales.ts` の言語名（先頭の空白、Lybia、Malay が 2 つ、システムの言語が大文字・小文字の違いで 2 回出る）、`emoji-search.ts` の先頭の説明
- 整理: 書式の `Qo`・`Mo`・`Wo`・`wo` は moment が読み返せない。今の確かめで弾かれているかを見て、ADR-0040 の表と合わせる
- 整理: ADR-0039 を守るテスト（`period-rules-guard.test.ts`）が、`.year()` や `.add(n, 'quarter')` を見ていない。`parsePeriod` が 1 月始まりのときだけ書き戻して確かめないのもそろえる
- 整理: テストを見直す。多すぎるテスト（同じことを何度も確かめている、作りの細部に頼っている）を消し、まとめるべきテストをまとめる。
  消す前に、そのテストだけが守っている振る舞いがないかを見る。夏時間のある時間帯（`TZ=America/Sao_Paulo` など）でも通るかも確かめる

### 決めること

- カレンダーの言語を変えると、週の始まりもその言語の既定に戻る（`src/stores/locale.ts` の `switchLocale`。わざとそうしている）。
  週の始まりが変わると、今ある週のノートが指す 7 日が変わる（[ADR-0011](adr/0011-week-follows-calendar.md)）。戻さないか、知らせるか — 自分
- Ctrl/Cmd を押しながら日付を押すと、新しいタブで開く（`getLeaf(true)`）。仕様は「横に開く」。どちらにするか（右クリックの「Open to the right」はある）— 自分
- 周期ノートかどうかを名前だけで決め、フォルダを見ていない（`src/io/validation/index.ts` の `isValidPeriodicNote`）。件数と移行は周期のフォルダの中だけ。
  フォルダの外の同じ名前のノートにも、ステッカーのボタンや前・次のノートを出してよいか — 自分
- 起動時に開く周期をオフにしてオンに戻すと、起動時に開く設定も黙って戻る。オフにしたときに消すか — 自分
- カレンダーの言語の既定を、OS の言語（`navigator.languages`）から取っている。仕様は「Obsidian の言語」。どちらに合わせるか — 自分
- 元の版の書式の一覧を 1 つにしたとき（読み込むとき）、使わなくなった書式のノートについて移行の知らせを出さない。元の版から移る人のために出すか — 自分

### 確かめる

- ペインを閉じたまま日付が変わっても、「今日」が新しくなるか — 自分。2026-11-01 に直した 6 件のうち、日付をまたがないと確かめられない最後の 1 つ
  （ほかの 5 件は 2026-11-01 に Obsidian で確かめた）。
  意図: 前は、カレンダーのペインの中のタイマーだけが「今日」を更新していた。今はプラグインが 1 分ごとに確かめる。
  手順: カレンダーのペインを閉じて、Obsidian を開いたまま日付をまたぐ → 翌日、Open now のボタンで今日のノートが開く。
  パンくずのミニカレンダーの「今日」も新しい日になっている
- Windows での確認（任意）— 自分

## 4. 公開すると決めたら

### 公開の手続き

決まりと要件、issue の下書きは [guides/publishing.md](guides/publishing.md)。上から順に進める。ただし issue は出したら返事を待つだけなので、
待つ間にほかを進める。「自分」は手でやること（GitHub への書き込み、決めごと、実機の確認）、「Claude」はコードや文書の作業。

- 元の作者の許可（公開すると決めたら、いちばん先。ほかを止める）
  - 下書きを読んで直す。特に、自分の名前・リポジトリの URL・変えたことの一覧 — 自分
  - issue を出す前に、GitHub のリポジトリを公開にするか決める（元の作者が改変の中身を見られるほうが判断しやすい。公開にしないなら、
    下書きからリポジトリへのリンクを消す）— 自分
  - issue を出す — 自分
  - 返事を待つ。許可が出たら、issue へのリンクを README のクレジットに書く。30 日たっても返事がなければ、B の形で進める — 自分
- `versions.json`（どの版がどの `minAppVersion` から動くかの対応表）を作るか決める。任意 — Claude
- リポジトリの整理
  - `CHANGELOG.md`: 今は元の版の履歴。消して、自分の版の最初のバージョンから英語で書き始める案 — 決めるのは自分
  - release-please の設定（`release-please-config.json`、`.release-please-manifest.json`）を消すか決める。2026-10-31 にワークフローを
    作り直して、もう使っていない — 自分
  - 既定のブランチを決める（`custom` のままか、`main` にするか）。審査は既定のブランチの先頭の `manifest.json` を読む — 自分
  - `upstream` の remote を、元のコードを見比べる参照用に残すか決める — 自分
  - GitHub のリポジトリ（small-spring/calendared）を公開にする。2026-10-30 の時点では外から見えない。README とライセンス表示が済んでから — 自分
- 確かめる
  - `npm test`・`npm run build`・`npm run deploy` が通る — Claude
  - Release から入れて動くか。BRAT でこのリポジトリを指定して入れるのが手軽 — 自分
  - 絵文字の検索の言語を、本番の版で jsDelivr から追加できるか（リポジトリを公開にしてから。取れないときに GitHub の raw から取れるかも）— 自分
- 申請（手順は guides/publishing.md の「申請の手順」）
  - Release を作る。`manifest.json` の `version` と同じタグを push すると、ワークフローが下書きを作る（[guides/development.md](guides/development.md) の「Release」）— 自分
  - community.obsidian.md でプラグインを登録する — 自分
  - 自動の審査で指摘されたら直す — Claude と自分
- 公開が済んだら、文書を切り替える — Claude
  - [customizations.md](customizations.md) を「公開までの改造の記録」として [archive/](archive/) に移し、以後の変更は英語の `CHANGELOG.md` に書く
    （GPL-3.0 の「改変したことと日付」は、README の告知・CHANGELOG・archive の記録で示し続ける）
  - [guides/publishing.md](guides/publishing.md) を archive/ に移し、毎回のリリースの手順を guides/release.md に書く

## 5. いつか（必要になったら・要望が出たら）

### ステッカー

- ステッカーを複数の種類に（例: 気分 `mood`、活動量 `activeness`）
  - 種類ごとにプロパティを 1 つ持ち、それぞれに絵文字を 1 つ付ける。カレンダーに出す種類を切り替える
  - 前に見送った「1 つのノートに複数のステッカーを並べる」とは別の考え（表示は常に 1 つなので、マスの表示を考え直さなくてよい）
  - [ADR-0001](adr/0001-sticker-in-one-property.md)（プロパティ 1 つ）を「種類ごとにプロパティ 1 つ」に広げる形。付ける操作（ピッカー）でどの種類かを選ぶ方法を考える
  - 種類ごとの設定（絵文字の選び方: すべてから / 候補を先頭に / 候補だけ）と付ける UI の案は [plans/sticker-kinds.md](plans/sticker-kinds.md)
- カレンダーの日付（や月）をダブルクリックして、ステッカーのピッカーを開く（近道）
  - そのノートを開いているときだけ有効にする。開いている日付のクリックは同じノートを開き直すだけなので、
      ダブルクリックをピッカーに割り当てても余計なことが起きず、ふだんのクリックも遅れない
  - 判定は「1 回目のクリックの時点で、すでに開いていたか」で行う（まだ開いていない日付を癖でダブルクリックした人にピッカーを出さない）
  - 隠れた操作なので、見える入口（見出しバーのボタン、コマンド、カレンダーの右クリック）の近道という位置づけ。スマホのダブルタップは要確認
- 絵文字ピッカーの乗り換え: 候補は emoji-picker-element（多言語のデータ emojibase で検索できる）。emoji-mart の更新が止まって困ったら

### 周期とノート

- 日・月のノートの名前を年度で書く（年度の年と四半期の記号を足す）。今は日・月の書式に `Q` を使えない（[ADR-0040](adr/0040-format-tokens-per-period.md)）。
  見直すきっかけ: 年度で名前を付けたいという声が出たら（パートナーに聞く）
- 学期（年を 2 つや 3 つに分ける）。四半期では表せない。要望が出たら考える

- 1 つの周期に、書式の違うデイリーノートを何種類も持てるようにする（例: 日記と作業ログ）
  - 2026-10-31 に書式を周期ごとに 1 つにした（[ADR-0019](adr/0019-one-format-per-period.md)）。複数の種類を使う人は、ほしくなるまで想定しない
  - 作るなら、書式だけでなく、種類ごとにフォルダ・テンプレートも持つ形にする。新しく作るときに、すべての種類をさっと作れる UI にする
  - 決めること: カレンダーは 1 日 1 ノートの作りなので、日付を押したときにどれを開くか、ステッカーや印をどれから取るか、パンくず・ミニカレンダーがどれを指すか
  - 設定の形は `periods.<周期>.format`（文字列 1 つ）なので、種類の一覧に広げるときは読み込むときに読み替える

### 移行

- 中身を書き換える移行（2026-10-30 に、同梱する移行はファイルの中身を書き換えないものだけにすると決めた。[spec/migrations.md](spec/migrations.md)）
  - 同じ日の 2 つのノートを 1 つにする: 書式の変換で名前がぶつかったとき。決めること: 付けるときの区切り（見出しや区切り線）、
    プロパティがぶつかったときの扱い、1 つにしたあと前のノートをどうするか
  - フォルダの移し替え: 中身は変えないので、書式の変換と同じ形で足せる
  - 元の版のステッカー（本文のタグ）をプロパティに移す
    - 書き換える前に、対象のノートと変更内容の一覧を見せる。ステッカーのつもりでないタグを書き換えないよう、対象を選べるようにする
  - 自分の Vault の移行はスクリプトとバックアップで行う。そこで起きたぶつかり方を、1 つにする機能を作るときの材料にする

### 移動と表示

- 月をいちばん短い周期で使う人に、ふつうのカレンダー（日付の表）も見せる（2026-11-01 に月の一覧にすると決めた。[ADR-0043](adr/0043-month-list-for-month-users.md)）。
  見直すきっかけ: そういう人から、ふつうのカレンダーが見たいという声が出たら（パートナーに聞く）
- 年のビューの 12 年の区切りを、今年を基準にする（過去を多めに。例えば今年が 3 段目に来るようにする）。今は 2020 起点の固定の区切り
  （`YEARS_RANGES_START`）なので、2031 年には今年が最後のマスに、2032 年には最初のマスに来て、残りがノートのない未来になる。
  1 月 1 日に区切りが 1 年ずれるが、日付が変わったときの更新（`src/today.ts`）に乗せられる。年のビューが出るのは年だけを使う人なので急がない
- 月・年のビューで、開いているノートを含む月（年）のマスを、開いている週の行と同じ薄い帯で塗る。「開いているノートの期間を、表のマスの細かさで塗る」
  という 1 つの決まりにし、週の行の帯もそれで書く（案は [ADR-0043](adr/0043-month-list-for-month-users.md)）。
