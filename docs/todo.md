## 1. 直すべき不具合

(1)(2) は 2026-10-28 に Cursor がコードを読んで見つけたもの、(3) は 2026-10-29 にそれを確かめる中で見つけたもの。
どれもコードを読んでの判断で、Obsidian ではまだ再現を確かめていない。(2)(3) は同じ処理（`src/main.ts` の `onFileDeleted`）なので一緒に直す。

- (1) 「Reveal on calendar」がそのノートの日付に行かない（`src/main.ts` の `onFileMenu`）
  - ファイルメニューでは `isValidPeriodicNote` から `date` と `granularity` が取れている
  - クリック時は `activeFileStore` の `file` だけ書き換え、`displayedDateStore` は `window.moment()`（今日）にしている
  - 去年のノートを Reveal すると今月が開き、選択の日付と粒度は前のまま残る
  - 直し方: 取ってある `date` と `granularity` を `activeFileStore` に入れ、`displayedDateStore` もその `date` にする（`onFileOpen` と同じ形）
- (2) 関係ないファイルを消すと、カレンダーの選択が外れる（`onFileDeleted`）
  - 消したファイルが今開いている周期ノートかどうかを見ずに、`activeFileStore` と `timelineParentFileStore` を空にしている
    （元のコードのコメントにも `this will add some cognitive load for sure` とある）
  - 別の日のノートや、周期ノートでない `.md` を消しただけでも、開いている日の選択の強調が消える。
    タイムラインの親が空になるのは、次の `layoutSync` で付け直されるだけなので実害は小さい
  - 直し方: 消したファイルが今の選択（とタイムラインの親）と一致するときだけ外す
- (3) ファイルを消すと、プレビューに表示中かどうかに関係なくプレビューが閉じる（`closePreviewOnFileDeleted`）
  - Cursor は「表示しているときだけ閉じるので、このままでよい」としていたが、そうなっていない
  - `ViewManager.searchPreviewLeaf(file)`（`src/ui/components/view/manager.ts`）の最初の判定は、プレビューのリーフなら
    ファイルを見ずに返す（ファイルの比較が同じリーフどうしなので常に真）。そのため、どの `.md` を消してもプレビューが閉じる
  - そのあとの `s.preview.open = false` は条件なしで実行される。この値は「カレンダーのタブに戻ったときにプレビューを開き直すか」に
    使われているので、関係ないファイルを消しただけで、次からプレビューが開き直らなくなる
  - 直し方: プレビューに表示中のファイルが消したファイルと一致するときだけ、閉じて `preview.open` を下ろす。
    `searchPreviewLeaf` の判定そのものを直すかは、ほかの呼び出し元（ファイルを渡していない）への影響を見て決める

## 2. やりたいこと

- ショートカットを Calendared のコマンドへ移す（2026-10-29 時点の Vault `private` の `.obsidian/hotkeys.json` を見たもの）
  - 今の割り当てと、移し先の候補:
    | 今のコマンド | キー | Calendared の移し先 |
    | --- | --- | --- |
    | `daily-notes`（コアのデイリーノート: 今日のノート） | Cmd+D | `create-current-daily-note`（Open daily note） |
    | `daily-notes:goto-prev`（前のデイリーノート） | Cmd+← と Cmd+Shift+, | なし（下の新しいコマンド） |
    | `daily-notes:goto-next`（次のデイリーノート） | Cmd+→ | なし（下の新しいコマンド） |
    | `calendar:show-calendar-view`（Calendar プラグイン） | Cmd+Shift+C | `toggle-calendar-view`（Toggle calendar interface） |
  - Calendar プラグインはもう入っていないので、Cmd+Shift+C は今は何もしていない。`periodic-notes` プラグインもフォルダだけ残っていて無効
  - Calendared の「Open previous/next ... note」は **今日** から前後に動くもので、開いているノートの前後ではない。
    コアの goto-prev / goto-next の代わりにはならない
  - **新しいコマンド**: 「開いている周期ノートの前／次を開く」を 1 組だけ作る（例: `open-previous-note` / `open-next-note`）
    - 開いているノートの周期（日・週・月・四半期・年）を見て、同じ周期で 1 つ前後へ動く。月次ノートなら前後の月、週次なら前後の週
    - 周期ノートを開いていないときはコマンドパレットに出さない（`checkCallback`）
    - 前後のノートがないときに作るか、ある所まで飛ばすか（コアの goto-prev はノートがある日まで飛ばす）は決める。
      周期が無効でノートもないときは作らない（今のルール）
  - 移すときは、コア側の割り当てを外してから Calendared に付ける（同じキーが 2 つに付くと衝突する）
  - **インストールしたら自動でショートカットが付くようにする** か検討
    - `addCommand` の `hotkeys` で既定のキーを指定できる。ユーザーが設定画面で変えたらそちらが優先される
    - Obsidian の公開プラグインのガイドラインでは、既定のホットキーは付けないよう勧められている（ほかのプラグインや OS と衝突するため）。
      自分用なら付けてよいが、公開するなら設定で「既定のキーを使う」を選べる形にするなど
    - Cmd+← / → は、編集中は行頭・行末へ移動するキーでもある（今もコアのコマンドがそれを上書きしている）
- 状態管理の作り直し（リファクタ段階 3）: ノートの一覧を設定から切り離す、`internalFileModStore` の `Math.random()` による合図をやめる、など。
  先に処理部分のテストを書いてから。上の不具合 (2)(3) のような「どの状態をいつ消すか」の食い違いを減らすのが目的の一つ
