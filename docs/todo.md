## 0. 元の版から独立して、コミュニティプラグインとして公開する

2026-10-29 に決めた方向。最終的には iPhone でも、BRAT を使わずにコミュニティプラグインから入れて使えるようにする。
下の 1〜3 よりこちらの決め事が先（削る機能の不具合は直さなくてよくなるため）。

### 方針

- **元の版の更新は取り込まない前提にする**（こだわらない）
  - [development.md](development.md) と `CLAUDE.md` の「元の版のファイルはなるべく変えない」決まりを外す
  - README を自分のものに書き直す（元の版のクレジットは残す）。CHANGELOG・release-please・`.github/` は自分の公開手順に合わせて作り直すか消す
  - `upstream` の remote は、元のコードを見比べる参照用に残すか決める
- **ライセンスは厳しいほうに従う**（パートナーの助言）
  - 元の版の LICENSE は GPL-3.0（`package.json` だけ MIT だった）。厳しいほうの GPL-3.0 に従い、改造版も GPL-3.0 で公開する
    （GPL の作品を改変したものなので、MIT などに変えることはそもそもできない）
  - 元の作者の著作権表示とクレジットを残す。改変したことと日付を示す（README の告知で済ませている）
  - 同梱している部品のライセンス表示: ビルドした `main.js` には依存パッケージ（emoji-mart、@emoji-mart/data、
    @floating-ui/dom、clsx、emoji-regex、uuid、svelte など）が入る。それぞれのライセンスを確かめ、求められる表示を
    `THIRD_PARTY_NOTICES.md` などにまとめる
  - `src/ui/utils/emoji-keywords/ja.json` は Unicode CLDR のデータから作ったもの。Unicode のライセンスが求める表示（著作権表示とライセンス文）を添える
- **自分が使わない機能は削る**（メンテナンスが大変なため。パートナーの助言）
  - カレンダーの表示は minimal mode だけにする。設定の `minimalMode` / `floatingViewAlwaysMinimal` と、minimal でない表示のコードを消す
  - 機能ごとの扱い（2026-10-29 に検討。カッコ内は Vault `private` の今の設定）:
    - **残す（決定）**
      - 起動時にノートを開く（`openAtStartup`）
      - カレンダーの言語の切り替え（`ja`、週は月曜はじまり）。ただし作りを直す（「2. やりたいこと」の「言語の扱いを直す」）
      - ステッカー（使っている）。複数の種類を持たせたい（「2. やりたいこと」）
      - 1 つの周期に複数のフォーマットを持つ機能: ファイル名の形式（例: `YYYY-MM-DD` と `YYYYMMDD`）を複数登録して両方を周期ノートと
        見なし、一覧・一括の移動・削除・形式の統一（名前の付け替え）をする機能。形式を途中で変えた人向け。
        自分は使わない（1 つずつ）ので、手入れの優先度は低い
    - **削る（決定）**
      - フローティング表示（オフ）、プレビュー欄（オフ）: 使っていない。作り直すかもしれない枠として「3. 必要になったら」に残す。
        プレビューを消すので、不具合 (3) は直さなくてよい
      - TODO の引き継ぎ: 作りの質が低いので一度消し、作り直す（「2. やりたいこと」の「TODO 管理」に、今の作りの問題点を書いた）
    - **作り直す（決定）**
      - 周期ノートでないノートにもタイムラインを出す（オフ）: オンにすると、ふつうのノートの右上にも今日の週のタイムラインが出て、
        そこからデイリーノートを開ける。機能としてはあってよいが、オンにすると挙動が不安定（不具合 (4)）。タイムラインの作り直しと一緒に直す
    - **削る方向（最終確認待ち）**
      - 自然言語の日付でノートを開くコマンド（`open-nldate-note`）: あまり要らない寄り
      - テンプレートの自然言語の置き換え（`{{next friday}}` など）: 使っていない。上のコマンドと同じ部品（chrono-node）なので、
        両方消せば依存が 1 つ減る
    - **テンプレートの置き換え（要判断）**: ノートを作るとき、テンプレートの `{{date:ddd}}`、`{{title}}` などを日付に置き換える機能
      - 自分の Vault では、デイリーの `{{date:ddd}}曜日`・`[[{{date:YYYY-MM}}]]` と、月次の dataviewjs の中の `{{date:YYYY-MM}}`・`{{title}}` が
        これで置き換わっている。月次の `<% %>` は Templater が置き換えている（Templater は新しく作られたノートの `<% %>` も処理する）
      - Templater だけで済ませることもできる: テンプレートを `<% moment(tp.file.title).format("ddd") %>` のような Templater の書き方に
        書き直せば、この機能は要らない
      - おすすめ: 基本の書き方（`{{date}}`、`{{title}}`、`{{time}}`、`:書式`、`+1d` のような足し引き）は残す。
        公開するなら Templater を入れていない人もいて、コアのデイリーノートも同じ書き方に対応しているので、ないと困る人が多い。
        小さい機能で、手入れもほとんど要らない
    - **minimal mode だけにする**（決定、`minimalMode` はオン）
  - 消したあとは、元の版の `data.json` に残った設定があっても動くことを確かめる

## 1. 直すべき不具合

(1)(2) は 2026-10-28 に Cursor がコードを読んで見つけたもの、(3)(4) は 2026-10-29 に見つけたもの。
(4) 以外はコードを読んでの判断で、Obsidian ではまだ再現を確かめていない。
(3) はプレビュー欄を削るので直さなくてよい（削るときに `onFileDeleted` から呼び出しごと消す）。

- (1) 「Reveal on calendar」がそのノートの日付に行かない（`src/main.ts` の `onFileMenu`）
  - ファイルメニューでは `isValidPeriodicNote` から `date` と `granularity` が取れている
  - クリック時は `activeFileStore` の `file` だけ書き換え、`displayedDateStore` は `window.moment()`（今日）にしている
  - 去年のノートを Reveal すると今月が開き、選択の日付と粒度は前のまま残る
  - 直し方: 取ってある `date` と `granularity` を `activeFileStore` に入れ、`displayedDateStore` もその `date` にする（`onFileOpen` と同じ形）
- (2) 関係ないファイルを消すと、カレンダーの選択が外れる（`onFileDeleted`）
  - 消したファイルが今開いている周期ノートかどうかを見ずに、`activeFileStore` と `timelineParentFileStore` を空にしている
    （元のコードのコメントにも `this will add some cognitive load for sure` とある）
  - 別の日のノートや、周期ノートでない `.md` を消しただけでも、開いている日の選択の強調が消える。
    タイムラインの親が空になるのは、次の `layoutSync` で付け直されるだけなので実害は小さい
  - 直し方: 消したファイルが今の選択（とタイムラインの親）と一致するときだけ外す
- (3) ファイルを消すと、プレビューに表示中かどうかに関係なくプレビューが閉じる（`closePreviewOnFileDeleted`）。**プレビューを削るので不要**
  - Cursor は「表示しているときだけ閉じるので、このままでよい」としていたが、そうなっていない
  - `ViewManager.searchPreviewLeaf(file)`（`src/ui/components/view/manager.ts`）の最初の判定は、プレビューのリーフなら
    ファイルを見ずに返す（ファイルの比較が同じリーフどうしなので常に真）。そのため、どの `.md` を消してもプレビューが閉じる
  - そのあとの `s.preview.open = false` は条件なしで実行される。この値は「カレンダーのタブに戻ったときにプレビューを開き直すか」に
    使われているので、関係ないファイルを消しただけで、次からプレビューが開き直らなくなる
  - 直し方: プレビューに表示中のファイルが消したファイルと一致するときだけ、閉じて `preview.open` を下ろす。
    `searchPreviewLeaf` の判定そのものを直すかは、ほかの呼び出し元（ファイルを渡していない）への影響を見て決める

- (4) タイムラインの付け替えが不安定（`src/ui/components/timeline/manager.ts`）
  - 症状（「ふつうのノートにも出す」をオンにしたとき、2026-10-29 に Obsidian で確認）: 月次ノートを開いても月次のタイムラインに
    切り替わらないことがある。ふつうのノートを開いたとき、畳まれたり畳まれなかったりする。前のノートの表示（月）が残る
  - 原因（コードを読んでの推定。再現手順で確かめる）:
    - **「今どのノートのタイムラインを出しているか」を、全体で 1 つの値（`timelineParentFileStore`）で覚えている。** タブ（リーフ）ごとではない。
      `layoutSync()` は、開いたノートがこの値と同じなら何もしない
    - しかもこの値は周期ノートのときしか更新しない。ふつうのノートにタイムラインを付けても、値は前の周期ノートのまま残る
      - 再現手順の予想: 月次ノート M を開く → 同じタブでふつうのノート N を開く（N 用の「今日の週」のタイムラインに替わる）→ M に戻る。
        値は M のままなので「もう M のタイムラインがある」と判断して何もせず、M に N 用のタイムラインが残る
      - **オフでも起きるはず**: M → N（タイムラインを外す）→ M で、M にタイムラインが出ない
    - 周期ノートどうしでタブを行き来すると、そのたびに作り直すので、週の移動や開閉の状態が毎回戻る
    - 畳むかどうかは、付けたときのペインの幅（640px より広いか）と設定（周期ノートは `viewMode`、ふつうのノートは `restViewMode`）で決まる。
      幅を測るのがペインの準備前だと 0 になり畳まれる。その後は `ResizeObserver` が幅の変化で開閉を切り替える（しきい値が 620・640・660 でばらばら）
    - 外すとき（`unmount(leaf)`、`mount` の中の `isMountedIn(leaf, true)`）は DOM の要素を消すだけで、Svelte の `unmount` を呼ばない。
      部品の後片付け（`ResizeObserver` の解除、ストアの購読の解除）が動かず、残り続ける。`components` は `file.path` で覚えているので、
      同じノートを 2 つのタブで開くと片方を見失う
  - 直し方（作り直し）: タブ（リーフ）ごとに「出しているタイムラインと、その対象のノート」を覚える（例: `WeakMap<WorkspaceLeaf, { file, component }>`）。
    ノートを開いたとき・タブを切り替えたときは、そのタブのノートと覚えているノートが違うときだけ付け替える。外すときは必ず Svelte の `unmount` を使う。
    開閉の初期値は、幅ではなく設定と前回の状態で決める
  - 方針（2026-10-29）: 部分的に直すのではなく、タイムラインの状態管理を設計し直す。下の「状態管理の作り直し（リファクタ段階 3）」と一緒に考える

## 3. 必要になったら

- フローティング表示・プレビュー欄を作り直す（2026-10-29 に一度削ると決めたもの。優先度低）
- 絵文字ピッカーの乗り換え: 候補は emoji-picker-element（多言語のデータ emojibase で検索できる）。emoji-mart の更新が止まって困ったら
- ステッカー関連
  - カレンダーの日付（や月）をダブルクリックして、ステッカーのピッカーを開く（近道）
    - そのノートを開いているときだけ有効にする。開いている日付のクリックは同じノートを開き直すだけなので、
      ダブルクリックをピッカーに割り当てても余計なことが起きず、ふだんのクリックも遅れない
    - 判定は「1 回目のクリックの時点で、すでに開いていたか」で行う（まだ開いていない日付を癖でダブルクリックした人にピッカーを出さない）
    - 隠れた操作なので、見える入口（見出しバーのボタン、コマンド、カレンダーの右クリック）の近道という位置づけ。スマホのダブルタップは要確認
  - 元の版のステッカー（本文のタグ）をプロパティに移す移行機能を、ステッカー機能とは別に作る
    - 書き換える前に、対象のノートと変更内容の一覧を見せる。ステッカーのつもりでないタグを書き換えないよう、対象を選べるようにする
