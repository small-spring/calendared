# 実機で試すための一度だけの準備（済み）

2026-10-30 に済ませた準備の手順。ふだんの使い方は [guides/device-testing.md](../guides/device-testing.md)。
端末を足すときや、同期の設定をやり直すときに見る。

## Remotely Save の暗号化

コードを同期する前にやっておく。Remotely Save の暗号化はパスワードで暗号化してから送るので、同期先を見られても中身は読まれない。
RClone Crypt 方式なら、パスワードを知らない人が書き換えたファイルは復号で失敗するので、差し替えにも強い（フォルダの構造は隠れない）。

あとから暗号化を有効にするときは、同期先のファイルを **すべて消して** から、暗号化したものを送り直す必要がある
（方式やパスワードを変えたときも同じ）。

### 注意: 前回の同期の記録

Remotely Save は前回の同期の記録を端末ごとに持っていて、それと比べて「どちらで消されたか」を決める。
同期先を空にしたあと、記録を残したまま同期すると、**同期先で消された** と読まれ、手元のノートまで消されるおそれがある。
なので、同期先を空にしたあとは、どの端末でも最初の同期の前に記録を消す（設定の下のほうの「Delete Prev Sync Details In DB」）。
記録を消すと、すべてのファイルが「新しく作られた」扱いになる。

### 手順

1. **すべての端末を同期しきってから、自動同期を止める**
   - 先に各端末で手動で同期し、どの端末にも最新のノートがある状態にする。それから Mac・Windows・iPhone の自動同期をすべてオフにする
2. **バックアップを取る**
   - Mac は Obsidian を閉じ、Vault を **丸ごと**（ノートも `.obsidian` も）Vault の外にコピーする
   - Windows・iPhone の `.obsidian` もバックアップする。ここにあるほかのプラグインとその設定は同期していないので、消えると戻せない
3. **同期先を空にする**
   - 消す代わりに、空の同期先を新しく作って Remotely Save の向き先を変えると、古い同期先がそのままバックアップになる
     （Cloudflare R2 などの S3 互換ではフォルダの名前を変えられないので、新しいバケットを作る。API トークンが新しいバケットにも使えるか確かめる）
   - 消すなら、クラウドのストレージの管理画面などから、Vault のフォルダの中身をすべて消す
   - 同期先を空にしても、同期するまで手元には何も起きない。手元が消されるのは、次の手順の記録の消去をせずに同期したとき
4. **Mac で暗号化を有効にして送り直す**
   1. Remotely Save の設定の「Encryption Password」にパスワードを入れ、「Confirm」と次の画面の確認ボタンで保存する
      （長く、ほかで使っていないもの。パスワード管理アプリに残す。忘れると同期先から戻せない）
      - 文字の種類や長さの制限はない（前後の空白だけ取り除かれる）。英数字だけで長くするのがよい。
        iPhone は打った `"` `'` `-` を別の文字に変えることがあり（スマート句読点）、端末ごとにパスワードが食い違うため、記号は避ける
   2. パスワードを保存すると「Encryption Method」が出てくるので、「RClone Crypt (recommended)」になっているか確かめる（初めからこれが選ばれている）
   3. 「Delete Prev Sync Details In DB」を押す
   4. 手動で同期する。同期先に、名前が読めない（暗号化された）ファイルが並べば成功
5. **Windows・iPhone で同じ設定にする**（1 台ずつ）
   1. 方式とパスワードを Mac と同じにする
   2. 「Delete Prev Sync Details In DB」を押す
   3. 手動で同期し、ノートが増えたり消えたりしていないか確かめる
      - 「Abort Sync If Modification Above Percentage」で止まる（ほぼ 100% が変わると出る）のは想定どおり。
        記録がないと、両方にあるファイルはすべて「ぶつかり」として数えられるため（新しいほうが残るだけで、消されるものはない）。
        この設定を一度 100（保護しない）にして同期し、終わったら元の値に戻す
   - うまくいかなければ、その端末の Vault を消して作り直し、Remotely Save を入れ直して同期する。
     そのあと手順 2 のバックアップから `.obsidian` を戻す（ほかのプラグインとその設定はこれでしか戻らない）
6. すべての端末で自動同期を元に戻す

## 一度だけの準備

先に上の「Remotely Save の暗号化」を済ませておく。
途中で問題が起きても戻せるように、同期を止め、バックアップを取ってから進める。

### 1. すべての端末で自動同期を止める

- Mac・Windows・iPhone それぞれで、Remotely Save の設定の自動同期（一定時間ごとの同期、起動時の同期、保存時の同期）をオフにする
- 作業中に別の端末が勝手に同期して、設定を上書きするのを防ぐため

### 2. Mac の `.obsidian` をバックアップする

- Obsidian を閉じてから、Vault の `.obsidian` フォルダを丸ごと、Vault の外にコピーする（例: 日付を付けたフォルダ名で）
- Windows・iPhone の `.obsidian` も、できればバックアップする（iPhone はファイルアプリからコピーできる場合がある）

### 3. Mac で設定する

先に 1 を済ませてから 2 をする（逆にすると、間の同期で `.obsidian` が丸ごと送られる）。

1. 「同期しないパス」に次の 1 行を足す（`.obsidian` の中のうち、`.obsidian/` と `plugins/` のフォルダそのものと、`plugins/calendared/` 以外は同期しない、という意味）

   ```
   ^\.obsidian/(?!$|plugins/$|plugins/calendared/)
   ```

   - Remotely Save は、無視したフォルダの中身もすべて無視する。なので `.obsidian/` と `plugins/` のフォルダそのものは無視しないようにしている
2. Remotely Save の設定で「設定フォルダも同期する」をオンにする

   - 端末ごとに Calendared の設定を変えたいときは、`^\.obsidian/plugins/calendared/data\.json$` も足す
     （足さなければ、週の始まりや書式などの設定も全端末で同じになる）

### 4. 送られる中身を確かめてから、手動で 1 回同期する

- コマンドパレットで「Remotely Save: start sync (dry run only)」を実行する（ファイルは変わらず、同期の予定だけが作られる）
- 続けて「Remotely Save: export sync plans (latest 1) (change part)」を実行すると、予定が `_debug_remotely_save/` にファイルとして書き出される
  （`_` で始まるフォルダは同期されない）。`.obsidian` の中で送られるのが `plugins/calendared/` の中だけか見る
- ほかのプラグインの設定や `community-plugins.json`、`hotkeys.json` などが含まれていたら **同期しない**。正規表現を見直す
- 問題なければ手動で同期する

### 5. Windows・iPhone で設定する

1. 手順 3 と同じ 2 つの設定を、同じ順でする
2. 手動で同期する。`.obsidian/plugins/calendared/` が届く
3. Obsidian の設定 →「コミュニティプラグイン」で、制限モードがオンならオフにし、Calendared を有効にする
   （有効なプラグインの一覧は同期しないので、端末ごとに一度だけ必要）
4. 動かなければ、Obsidian を再起動する

### 6. 自動同期を戻す

- すべての端末で、手順 1 で止めた自動同期を元に戻す
