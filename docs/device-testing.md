# 実機での確かめ方（Windows・iPhone）

開発は Mac で行い、`npm run deploy` で Mac の Vault にプラグインを入れる（[development.md](development.md)）。
ほかの端末（Windows、iPhone）では、Remotely Save で **Calendared のフォルダだけ** を同期して試す。

コミュニティプラグインとして公開したあとは、どの端末でもプラグインの一覧から入れられるので、この手順は要らなくなる。

## しくみ

- Obsidian のプラグインは、`.obsidian/plugins/<id>/` フォルダの中のファイルがすべて
  - `main.js`（プログラム）、`manifest.json`（名前とバージョン）、`styles.css`（見た目）、`data.json`（設定。あれば）
  - 「インストール」はこのフォルダを置くことと同じ。コミュニティプラグインの一覧や BRAT も、裏ではこれらのファイルを置いているだけ
- なのでフォルダを同期すれば、届いた端末でそのまま動く。iPhone の Obsidian も同じ `main.js` を動かす
  （Calendared はパソコンにしかない機能（Node.js、Electron）を使っていない）
- Remotely Save の設定（0.5.25 で確認）
  - 「設定フォルダも同期する」（`syncConfigDir`）: `.obsidian` フォルダも同期の対象に入れる
  - 「同期しないパス」（`ignorePaths`）: 正規表現で指定したパスを同期から外す
  - 「同期するパスだけ」（`onlyAllowPaths`）は Vault 全体に効き、ノートまで同期されなくなるので **使わない**
- Remotely Save の設定は端末ごと。どの端末にも同じ設定が要る

## 危険性

iOS も Obsidian も、同期で届いた `main.js` を検査しない（署名の確認などはない）。
なので「iPhone 側で危ないと判定される」ことはない。気をつけるのは次のこと。

- **同期先に書き込める人は、すべての端末でコードを動かせる**
  - 同期先（クラウドのストレージ）の `main.js` を差し替えられると、それが Mac・Windows・iPhone で動く。
    プラグインは Vault のファイルをすべて読み書きでき、ネットにもつながる
  - ほかのプラグインの `data.json` も読める。Remotely Save の `data.json` には同期先の鍵とパスワードが平文で入っている
  - 対策: 同期先のアカウントを固める（二段階認証など）。Remotely Save の暗号化を使う（[下の手順](#remotely-save-の暗号化)）。
    **Remotely Save のフォルダは同期しない**（手順 3 の正規表現で外れている）
- **開発中の不具合がすべての端末に広がる**
  - Calendared はノートを作ったり名前を変えたりする。不具合のある版を同期すると、どの端末でも同じことが起き、ノートの同期でさらに広がる
  - Mac でひととおり動かしてから同期する。作り直しの途中の版は送らない
- **中途半端に届くと動かない、または固まる**
  - 同期が途中で止まると `main.js` と `manifest.json` の版が食い違うことがある。ふつうは読み込みに失敗するだけ
  - 読み込み中に無限ループなどがあると、起動のたびに固まる。iPhone では開発者向けの画面がないので、
    「ファイル」アプリから `.obsidian/plugins/calendared/` を消すか、`.obsidian/community-plugins.json` から `calendared` を外す
    （Vault が「この iPhone 内」にある場合）
- **iPhone の JavaScript は少し古いことがある**
  - iOS の Obsidian は Safari と同じしくみで動く。iOS が古いと新しい書き方が使えない。Mac で動いて iPhone で動かないときはまずこれを疑う

## Remotely Save の暗号化

コードを同期する前にやっておく。Remotely Save の暗号化はパスワードで暗号化してから送るので、同期先を見られても中身は読まれない。
RClone Crypt 方式なら、パスワードを知らない人が書き換えたファイルは復号で失敗するので、差し替えにも強い（フォルダの構造は隠れない）。

あとから暗号化を有効にするときは、同期先のファイルを **すべて消して** から、暗号化したものを送り直す必要がある
（方式やパスワードを変えたときも同じ）。

### 注意: 前回の同期の記録

Remotely Save は前回の同期の記録を端末ごとに持っていて、それと比べて「どちらで消されたか」を決める。
同期先を空にしたあと、記録を残したまま同期すると、**同期先で消された** と読まれ、手元のノートまで消されるおそれがある。
なので、同期先を空にしたあとは、どの端末でも最初の同期の前に記録を消す（設定の下のほうの「Delete Prev Sync Details In DB」）。
記録を消すと、すべてのファイルが「新しく作られた」扱いになる。

### 手順

1. **すべての端末を同期しきってから、自動同期を止める**
   - 先に各端末で手動で同期し、どの端末にも最新のノートがある状態にする。それから Mac・Windows・iPhone の自動同期をすべてオフにする
2. **バックアップを取る**
   - Mac は Obsidian を閉じ、Vault を **丸ごと**（ノートも `.obsidian` も）Vault の外にコピーする
   - Windows・iPhone の `.obsidian` もバックアップする。ここにあるほかのプラグインとその設定は同期していないので、消えると戻せない
3. **同期先を空にする**
   - 消す代わりに、空の同期先を新しく作って Remotely Save の向き先を変えると、古い同期先がそのままバックアップになる
     （Cloudflare R2 などの S3 互換ではフォルダの名前を変えられないので、新しいバケットを作る。API トークンが新しいバケットにも使えるか確かめる）
   - 消すなら、クラウドのストレージの管理画面などから、Vault のフォルダの中身をすべて消す
   - 同期先を空にしても、同期するまで手元には何も起きない。手元が消されるのは、次の手順の記録の消去をせずに同期したとき
4. **Mac で暗号化を有効にして送り直す**
   1. Remotely Save の設定の「Encryption Password」にパスワードを入れ、「Confirm」と次の画面の確認ボタンで保存する
      （長く、ほかで使っていないもの。パスワード管理アプリに残す。忘れると同期先から戻せない）
      - 文字の種類や長さの制限はない（前後の空白だけ取り除かれる）。英数字だけで長くするのがよい。
        iPhone は打った `"` `'` `-` を別の文字に変えることがあり（スマート句読点）、端末ごとにパスワードが食い違うため、記号は避ける
   2. パスワードを保存すると「Encryption Method」が出てくるので、「RClone Crypt (recommended)」になっているか確かめる（初めからこれが選ばれている）
   3. 「Delete Prev Sync Details In DB」を押す
   4. 手動で同期する。同期先に、名前が読めない（暗号化された）ファイルが並べば成功
5. **Windows・iPhone で同じ設定にする**（1 台ずつ）
   1. 方式とパスワードを Mac と同じにする
   2. 「Delete Prev Sync Details In DB」を押す
   3. 手動で同期し、ノートが増えたり消えたりしていないか確かめる
      - 「Abort Sync If Modification Above Percentage」で止まる（ほぼ 100% が変わると出る）のは想定どおり。
        記録がないと、両方にあるファイルはすべて「ぶつかり」として数えられるため（新しいほうが残るだけで、消されるものはない）。
        この設定を一度 100（保護しない）にして同期し、終わったら元の値に戻す
   - うまくいかなければ、その端末の Vault を消して作り直し、Remotely Save を入れ直して同期する。
     そのあと手順 2 のバックアップから `.obsidian` を戻す（ほかのプラグインとその設定はこれでしか戻らない）
6. すべての端末で自動同期を元に戻す

## 一度だけの準備

先に [Remotely Save の暗号化](#remotely-save-の暗号化) を済ませておく。
途中で問題が起きても戻せるように、同期を止め、バックアップを取ってから進める。

### 1. すべての端末で自動同期を止める

- Mac・Windows・iPhone それぞれで、Remotely Save の設定の自動同期（一定時間ごとの同期、起動時の同期、保存時の同期）をオフにする
- 作業中に別の端末が勝手に同期して、設定を上書きするのを防ぐため

### 2. Mac の `.obsidian` をバックアップする

- Obsidian を閉じてから、Vault の `.obsidian` フォルダを丸ごと、Vault の外にコピーする（例: 日付を付けたフォルダ名で）
- Windows・iPhone の `.obsidian` も、できればバックアップする（iPhone はファイルアプリからコピーできる場合がある）

### 3. Mac で設定する

1. Remotely Save の設定で「設定フォルダも同期する」をオンにする
2. 「同期しないパス」に次の 1 行を足す（`.obsidian` の中のうち、`plugins/calendared/` 以外は同期しない、という意味）

   ```
   ^\.obsidian/(?!plugins/calendared/).*
   ```

   - 端末ごとに Calendared の設定を変えたいときは、`^\.obsidian/plugins/calendared/data\.json$` も足す
     （足さなければ、週の始まりや書式などの設定も全端末で同じになる）

### 4. 送られる中身を確かめてから、手動で 1 回同期する

- Remotely Save に同期の予定を確かめる機能（ドライラン、ログ）があれば使い、`.obsidian` の中で送られるのが `plugins/calendared/` の中だけか見る
- ほかのプラグインの設定や `community-plugins.json`、`hotkeys.json` などが含まれていたら **同期しない**。正規表現を見直す
- 問題なければ手動で同期する

### 5. Windows・iPhone で設定する

1. 手順 3 と同じ 2 つの設定をする
2. 手動で同期する。`.obsidian/plugins/calendared/` が届く
3. Obsidian の設定 →「コミュニティプラグイン」で、制限モードがオンならオフにし、Calendared を有効にする
   （有効なプラグインの一覧は同期しないので、端末ごとに一度だけ必要）
4. 動かなければ、Obsidian を再起動する

### 6. 自動同期を戻す

- すべての端末で、手順 1 で止めた自動同期を元に戻す

## ふだんの流れ

1. Mac で `npm run deploy`（Mac の Vault の Calendared が新しくなる）
2. Mac で同期する
3. ほかの端末で同期し、Obsidian を再起動する（またはプラグインをオフ → オン）

## うまくいかなかったとき

- **ほかのプラグインの設定が上書きされた**: Obsidian を閉じ、手順 2 のバックアップから `.obsidian` を戻す。
  上書きされた端末で同期する前に、ほかの端末の自動同期が止まっているか確かめる
- **Calendared が届かない**: 「設定フォルダも同期する」がオンか、正規表現が `plugins/calendared/` を外していないかを確かめる。
  正規表現の「〜以外」（`(?!…)`）が効かない場合は、ほかのプラグインのフォルダを 1 つずつ外す書き方に変える
- **届いたが動かない**: Obsidian を再起動する。プラグインのバージョン（`manifest.json`）が Mac と同じか確かめる。
  iPhone なら、開発者向けのログが見られないので、Mac で同じ操作をして再現するか確かめる

## 端末ごとに確かめること

- **Windows**: 見た目（フォントや拡大率でヘッダーの幅やタイムラインが崩れないか）、ファイル名（Windows で使えない文字 `: ? * " < > |` が書式に入っていないか）、
  ショートカット（Mac の Cmd は Windows の Ctrl。ホットキーは端末ごとに設定が要る場合がある）
- **iPhone**: 狭い画面での見た目、タップ・長押し（右クリックの代わり）、ホバーを前提にした機能（Hover preview など）が使えるか
