# ADR-0034 ほかのプラグインの設定は読み取らず、いつも Calendared の既定値から始める

- **背景**: [ADR-0023](0023-migrations-without-content-changes.md) と [ADR-0027](0027-no-core-daily-notes-settings.md) で、初めて入れたときに
  コアのデイリーノートや Periodic Notes の書式・フォルダ・テンプレートを既定値として読み取ると決めていた。黙って読むか聞くか、両方あるときに
  どちらを使うかが決まっていなかった
- **検討した案**
  - A. 黙って読み取り、どこから取ったかを設定画面に一言出す
  - B. 初めて入れたときに「使いますか」と聞く
  - C. 移行のサブページに「取り込む」ボタンを置き、押したときだけ読む
  - D. 読み取らない。いつも Calendared の既定値から始める
- **決定**: D
- **理由**
  - A は「読み取った」という一言をいつ消すかが決まらない。出し続けるのも、黙って消すのも落ち着かない
  - B は、入れた直後にはまだ何のことかわからない人が多い
  - C は形としては一番すっきりしているが、合わせる設定は周期ごとに書式・フォルダ・テンプレートの数か所で、手で入れても手間は小さい。
    まず使ってもらう相手（パートナー）にも要らない
  - 作るものが 1 つ減り、両方あるときにどちらを使うかも決めなくてよくなる
- **結果**: 乗り換える人は、書式とフォルダを手で合わせる。合わせないと、今あるノートがカレンダーに出ない。
  C は [todo.md](../todo.md) の「見送ったこと」に置き、乗り換える人から声が出たら足す。
  コアのデイリーノートがオンのときは、設定画面にごく弱い警告を出す（同じ日のノートが 2 つできうるため。[plans/settings.md](../plans/settings.md) の「周期ノート」）
