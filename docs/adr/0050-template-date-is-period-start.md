# ADR-0050 テンプレートの {{date}} は、ノートの期間の最初の日にする（作った日時は {{currentDate}}）

- **背景**: 週・月・四半期・年のノートは何日もの期間を指すので、テンプレートの `{{date:YYYY-MM-DD}}` のように日まで書く書式では、
  どの日を入れるかが原理的に一意に決まらず、決めごとが要る。2026-11-01 まで、起動時に開くノートだけが「今」を渡していて、
  コマンドやカレンダーから作ったとき（期間の最初の日）と中身が食い違っていた
- **検討した案**
  - A. 期間の最初の日（週の始まり、四半期・年は始まりの月の 1 日）
  - B. 作った日
  - C. その周期をまるごと含まない記号（週のノートの `DD` など）を書いたら、置き換えずに失敗させる（ADR-0040 の考えをテンプレートにも広げる）
- **決定**: A
- **理由**
  - ノートは今日以外の期間にも作れる（カレンダーから先週・来月を作る）。B だと、名前の期間と中身の日付がずれる
  - どこから作っても（コマンド・起動時・カレンダー・Open now）同じ中身になる
  - 作った日時がほしいときのために、`{{currentDate}}`・`{{time}}` が別にある。`{{date}}`・`{{title}}` は「ノートの日付」、
    `{{currentDate}}` は「作ったとき」と分けて考えられる
  - C は、週のノートに `{{date:YYYY-MM-DD}}` と書いて週の始まりの日として使う、よくある書き方（元の版・Periodic Notes で動く）を壊す。
    テンプレートの中身はノートを作るときにしかわからないので、失敗を設定画面で先に止められず、作るときの知らせになる
- **結果**: `{{date}}` にはどの作り方でも `periodStart` を渡す。README と日本語の使い方に、`{{date}}` は期間の最初の日、
  作った日は `{{currentDate}}` と書いた
- **気になっていること**: A は「代表の日」を決めているだけで、とても気に入っている決め方ではない（2026-11-02）。
  見直すきっかけ: パートナーが週・月のテンプレートで `{{date}}` の日付にとまどったら。C や、期間を書く置き換え（`{{start}}`・`{{end}}` など）を考え直す
