# ADR-0044 周期ノートとして扱うのは、その周期のフォルダ（とその下）のノートだけにする

- **背景**: 開いているノートが周期ノートかどうか（`isValidPeriodicNote`）は、名前だけで決めていた。
  一方、設定画面の件数と移行（`notesWithFormat`）は、その周期のフォルダ（とその下のフォルダ）の Markdown だけを数える。
  そのため、例えば日のフォルダを「日記」にしていても、ほかのフォルダにある `2026-10-29` という名前のメモに、
  ステッカーのボタン・パンくず・ミニカレンダーが出て、前後のノートのコマンドや Open now の「今のノート」の判定にも入った。
  件数には入らず、移行もされないノートなのに、周期ノートのようにふるまっていた
- **検討した案**
  - A. 今のまま名前だけで決める（どこに置いても周期ノートとして扱う）
  - B. その周期のフォルダの直下だけ（カレンダーがノートを探す場所と同じ）
  - C. その周期のフォルダとその下のフォルダ（件数・移行と同じ）
- **決定**: C。あわせて、Markdown でないファイルは周期ノートとして扱わない
- **理由**
  - 件数・移行と同じ決まりにすると、「設定画面で数えられるノート」と「周期ノートとしてふるまうノート」が一致する
  - 年ごとのフォルダ（`日記/2026/2026-10-29.md`）に分けて置く人がいる。B にすると、そうしたノートが件数には入るのに、
    ステッカーのボタンやパンくずが出なくなる
  - 名前だけで決めると、フォルダを分けて別の用途に日付の名前を使う人（記録用のフォルダなど）のノートまで巻き込む
- **結果**: パンくず・ミニカレンダー、ステッカーのボタンとコマンド、前後のノートのコマンド、Open now の判定、ノートを開いたときに
  カレンダーの月を合わせること、書式がまちがっているという知らせが、どれもこの決まりで周期ノートを見分ける（ノートのパスを渡す）。
  カレンダーのマスは今までどおり、周期のフォルダの直下の、書式が書く名前のノートを指す。下のフォルダのノートは、
  開けば周期ノートとしてふるまうが、カレンダーのマスからは開けない（前からの違いで、今回は変えない）
