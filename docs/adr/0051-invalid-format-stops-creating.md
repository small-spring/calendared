# ADR-0051 書式がまちがっていたら、ノートを作る所で止めて知らせる（すでにあるノートは開く）

- **背景**: まちがった書式は、設定画面でエラーを出し、設定画面を完全に閉じたときに既定へ戻している（ADR-0040）。
  2026-11-02 の手での確認で、周期のサブページから Esc で一つ上に戻っただけでは閉じたことにならず、その間に
  コマンドやカレンダーから、まちがった書式の名前（日の書式 `YYYY-MM` なら `2026-11.md`）のノートが作れるとわかった
- **検討した案**
  - A. ノートを作る所（`createOrOpenNote`）で書式を確かめ、まちがっていれば作らずに知らせる。すでにあるノートは開く
  - B. A と同じだが、すでにあるノートを開くのも止める
  - C. 設定の欄にまちがった書式を保存しない（欄に残すだけにする）
  - D. サブページから戻ったときにも既定へ戻す
- **決定**: A
- **理由**
  - 作る道（カレンダーの日付、コマンド、起動時、Open now、パンくず）はどれも `createOrOpenNote` を通るので、1 か所で全部止まる
  - 困るのは変な名前のノートが「できる」ことだけ。すでにあるノートを開いても何も壊れない。オフの周期と同じ考え（作るのだけ止める）にそろう
  - 設定の欄にまちがった書式を残せるのは今のまま（入力の途中で消えたり戻ったりしない）。C だと保存とエラーの関係が今より込み入り、
    D は「どこで閉じたことにするか」の見張りが増えるうえ、ほかの道（設定の外から data.json を書き換えたなど）は防げない
  - 確かめの画面（Confirm before creating notes）より前に止める。作れないのに「作りますか」と聞かない
  - 空（空白だけ）の書式も止める。設定画面では入力の途中なのでエラーにしないが、ノートの名前が時刻や空白になる。
    閉じるときに既定へ戻す判定（`formatsToReset`）も同じ `noteFormatError` を使う
- **結果**: 知らせは「Daily note format is invalid: 〈設定画面と同じ誤りの文〉」（`invalidFormatMessage`、周期の言葉は `period-words.ts`）。
  オフの周期は、書式がまちがっていても、オフの知らせが先に出る。README と日本語の使い方に書いた
