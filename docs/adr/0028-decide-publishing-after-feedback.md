# ADR-0028 公開するかは、機能を詰めてパートナーに使ってもらってから決める

- **背景**: 2026-10-30 の時点では、わかっている不具合を直したらコミュニティプラグインとして公開する前提で、公開の手続き
  （元の作者の許可、manifest、README、ワークフローなど）を作業の一覧に並べていた。ただ、自分以外の人が使ってどう感じるかは、まだ確かめていない
- **検討した案**: A. 前提どおり、不具合を直したら公開する / B. 機能を詰め、パートナーに使ってもらってフィードバックをもらい、そのあとで公開するか決める
- **決定**: B
- **理由**: 公開すると、元の作者への連絡や審査、その後の手入れなど、戻しにくい手間が増える。先に身近な人に使ってもらえば、
  ほかの人にも役立つか、わかりにくい所はどこかを、手間をかける前に確かめられる。公開の手続きは、決めてから進めても遅れは小さい
- **結果**: 作業の順番は [todo.md](../todo.md) の 1〜4（機能を詰める → パートナーに使ってもらう → 公開するか決める → 公開すると決めたら）。
  公開の手続きには、公開すると決めるまで手を付けない。元の版の更新を取り込まない方針は変えない。
  リポジトリを公開するまでは、絵文字の検索の言語のダウンロード（jsDelivr）は本番の版では失敗するので、パートナーに渡すときに考える
